# v0.11 — URDF import and checked mechanism export

FluxKernel can now import a supported URDF tree into its native robot model,
regenerate URDF/MJCF, and run Lean checks on selected fields read from the actual
exported URDF. This closes the missing reverse import path and detects changes
between the native mechanism and its exchange document.

Implementation: `2fb62177e405ce23a34d5924cbda13099d6a2302`.
The [usage and scope guide](../URDF_BRIDGE.md) documents the command, supported
subset, assumptions, certificate and trusted input boundary.

```bash
fk robot import-urdf robot.urdf --output robot-runs --require-proof
fk robot verify robot-runs/urdf-<id> --require-proof
fk robot check-projection robot-runs/urdf-<id>
```

The [benchmark](2026-09-28-v0.11-evidence/roundtrip.json) imports each existing
robot's URDF, then imports the resulting URDF again. All four cases and eight
new bundles passed both Lean proofs and independent projection checks. Original
source bundles remained unchanged. This engineering validation made zero model
calls; personalized inputs are the previously selected v0.10 GLM artifacts.

Each new bundle was compared with three consumers at three configurations,
giving 72 comparison rows across eight bundles. Checks cover frames, mass, COM,
world inertia and mesh bounds/centroids. The largest reported frame component
error was `1.583e-11`; the largest mesh-moment coordinate error was `8.630e-8 m`.
These sampled numerical checks do not establish equivalence at every configuration.

The evidence folders preserve each bundle's proof instances, Lean logs, import
assumptions and projection results. Source license notices are included; full
native bundles and source assets remain in `.demo/v011-validation/roundtrip/`.

All four generated URDFs passed the URDF skill's generator validation. The local
CAD Viewer does not load native OBJ assets, so

## Proof boundary and compatibility

The exchange certificate establishes equality of link names/masses, joint
identity/topology/types/axes, reference-shifted position bounds, and declared
effort/velocity values for the supported finite records. Python extraction and
XML parsing remain trusted. Frame transforms, inertia decomposition and mesh
geometry receive numerical checks, not Lean proofs. This release does not prove
complete exporter correctness, physical feasibility or control safety.

The workflow is URDF → native model → checked URDF/MJCF. A Lean instance alone
does not carry enough information to reconstruct an arbitrary robot. Unsupported
URDF constructs are rejected explicitly; controller contracts, source lineage and
physical evidence cannot be recovered from ordinary URDF. Imported robots remain
`deployment_ready=false`.

Existing v0.9/v0.10 bundles still verify with the exchange certificate explicitly
unavailable. They are not retroactively relabeled. New imports and revisions carry
the additional certificate. Implementation and proof evidence remain in the
private repository.
