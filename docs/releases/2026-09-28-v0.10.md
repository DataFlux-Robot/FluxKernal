# v0.10 — GLM-only native robot accessory personalization

GLM delivery workflow commit: `2b90ae3650ea474a2df891994467171fe8e22a49`.
The later standalone snapshot camera fix is `b7a875f4372238bd576825a04ddf2ece6df16330`; its targeted regression and rebuilt-wheel smoke also passed.
GitHub CI is still running at the recorded handoff snapshot: [status](2026-09-28-v0.10-evidence/ci.json), [live run](https://github.com/ExuberantWitness/fluxkernel/actions/runs/36426422815).

A user brief now drives a bounded GLM-5.3-Flash loop that adds a decorative part to
an imported Microduck or XGO native model. The model chooses the geometry, symmetry,
revisions and final candidate. The host preserves the original mechanism, builds
STEP/STL, generates the native variant and URDF/MJCF, checks geometry and sampled
clearance, and returns actual renders for model review.

This pilot adds a small head-top accessory. It does not replace a complete shell,
recover mounting holes, generate arbitrary mesh styles, or qualify an installed
upgrade. The [usage guide](../ROBOT_PERSONALIZATION.md) describes the commands and
remaining operators. Open the [offline evidence page](2026-09-28-v0.10-evidence/index.html)
to inspect the results.

## Verification

- [272 tests passed](2026-09-28-v0.10-evidence/tests.txt), including 16 accessory
  tests covering SI mass/inertia against an analytic cylinder, trimmed curved STEP
  round-trip, immutable mechanisms, stale contracts, artifact tampering, CAD-backed
  revision guards and rejected-plan feedback. Mock provider tests are explicitly
  labeled; the delivery runs above use the actual provider.
- [Isolated wheel installation](2026-09-28-v0.10-evidence/wheel.json) exercises core,
  Studio, real Lean, MCP stdio, native robot projections and an authored accessory
  fixture outside the checkout, without a model account.
- [Microduck](2026-09-28-v0.10-evidence/microduck/independent.json) and
  [XGO](2026-09-28-v0.10-evidence/xgoduck/independent.json) independent verification
  reruns Lean, checks MJCF/URDF frame/mass/inertia/mesh consistency, and confirms the
  source parents' content hashes are unchanged.
- The sampled distance test uses convex hulls, excludes the intended target contact
  and permits at most 0.2 mm penetration. It is not continuous collision coverage,
  curved-surface fit, camera FOV, strength, or physical gait testing.
- Mass is solid CAD volume times nominal polymer density. Volume uses Gauss-Kronrod
  integration; COM/inertia use fixed Gaussian integration with mass normalization.
  These are numerical estimates, not measured print properties. Lean checks finite
  native structure/controller obligations; CAD/frozen-record tests are separate.

## Development failures are retained

The [history](2026-09-28-v0.10-evidence/run-history.json) records ten development
runs and 45 archived provider responses, including the two delivery runs (13 calls).
Three-round limits apply per run, not to the entire debugging campaign. Earlier runs
exposed prose-wrapped JSON, disconnected/below-plane geometry, STEP volume
integration differences and pathological all-moment integration cost. One stalled
run was explicitly interrupted by the host; it was not a model rejection or success.
Two earlier selected runs were superseded after an inertia regression failed.

Workflow changes always led to fresh identities. No model recipe was manually
repaired or substituted. The final workflow carries failed recipes and diagnostics
back to GLM, retains rejected candidates, and permits null selection.

## CAD tooling and remaining physical work

The installed CAD skill generation/inspection/snapshot helpers fail against OCP 8
because `TDF_LabelSequence` is unavailable. The installed CAD Viewer lacks
`agent:start`. [Failure logs](2026-09-28-v0.10-evidence/cad-viewer.txt) and per-platform
helper logs are retained. The primary STEP was instead read independently, checked
for one valid solid and matching volume, and rendered through MuJoCo. Separate part
snapshots are included alongside whole-robot and head views; no live Viewer link is
claimed. A subsequent presentation-only camera change creates `part-detail.png`
from the selected STEP bounds. These additional close-ups were produced after
selection and were not model inputs. Original `part.png` and workflow snapshots
remain unchanged.

The contact datum is a source triangle tangent. A flat pad on a curved head is only
a mounting proposal. Curvature fit, adhesive retention, camera view, cooling,
slicing/print process and walking remain open. Next work is a verified adapter and
physical-part/BOM mapping, followed by shell replacement with correct mass
subtraction/addition and control revalidation.

Anything2Robot inspired the integration assessment, but no implementation from it
was copied or executed. Its stated commercial-use restriction remains relevant for
any future direct integration; see the [source review](../ROBOT_PERSONALIZATION.md).
