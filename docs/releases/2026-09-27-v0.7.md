# FluxKernel v0.7 — whole-body and assembly workflow

The aircraft refinement loop could mirror disconnected parts and adjust independent
fuselage templates without producing a coherent overall body. v0.7 gives GLM a shared
body profile, manufacturing partition boundaries, parent/child anchors and explicit
axis alignment. The tool compiles those declarations; GLM still authors geometry
parameters, reviews renders, issues edits and selects the retained candidate.

## What changed

- A model-declared complete body profile is partitioned into existing fabricated
  occurrences with shared boundary ellipses. IDs, materials, routes and procurement
  dimensions stay fixed. Body parameters and partition positions can be revised.
- Acyclic attachment/mirror dependencies derive child translations. Wing, body,
  box and cylinder anchors use the actual recipe coordinate conventions, including
  local reflections. Declared axis directions derive part rotations.
- Independent checks report body seam error, anchor error, axis error and actual
  B-rep contact distance, including mirrored contacts. The corrected runtime also
  reports closest surface points and world gap vectors, including informative
  distances for placement relationships.
- Edits can restructure attachment parents and body partitions. Contact, axis and
  shared-body verification coverage cannot be dropped mid-run to hide a failure.
- Scalar coordinate claims accept both `position.1` and `position.y`, checking the
  same actual number. Entire vectors and explanatory text remain invalid claims.
- CLI/Studio allow up to eight reviews. Three reviews still provide only two
  post-planning action opportunities; more budget is not a convergence guarantee.

The runtime [skill](../../fluxkernel/demo/skills/fluxkernel-glm-pal/SKILL.md) and
[parameter contract](../../fluxkernel/demo/skills/fluxkernel-glm-pal/references/parameters.md)
are injected into every model phase. No live candidate was manually edited and no
host visual ranking selected the output. Every rejected attempt is retained.

## Experiment protocol

All four live attempts start from the same unchanged parent, `c59d5c0edad34a94`,
the v0.6 aircraft previously shown to the user. Two finite review budgets, 3 and 6,
were run under each frozen implementation. The first pair exposed a scalar-claim
notation failure; only after both finished was the general protocol/feedback updated.
No intermediate candidate or model response was patched or replayed.

- Initial runtime: `01a57b6eee428d06629db4670d0241d72bca3dce`.
- Corrected runtime: `23225277e64979f42403d4975e6bc71d78e9e558`.
- Provider requested and reported model: `glm-5.3-flash`.
- Predeclared measurements: engine-axis diagnostics and actual surface gaps for
  both main-wing/winglet pairs and four fuselage adjacencies.
- Protocols and complete attempt accounting are in [the evidence directory](2026-09-27-v0.7-evidence/).

Only one stochastic attempt per budget per implementation was run. This is a small
engineering validation, not a statistically reliable budget ablation or comparison
against another model. Model ratings are not calibrated similarity scores.

## Scope and remaining limitations

This is an OpenVSP-inspired bounded geometry vocabulary, not an OpenVSP integration.
Shared profiles provide C0 boundary continuity, not guaranteed tangent/curvature
continuity or hollow production shells. The operation restructures existing parts;
it does not implement arbitrary part insertion/deletion or recover unseen internals.

Contact distance zero can include intersecting/contained solids. Placement relations
are deliberately not claims of contact, and undeclared relationships are unassessed.
No general penetration solver, camera alignment, silhouette IoU or physical validation
was added. GLM may still understate visible defects even when all declared contact
checks pass. A model threshold is not human visual acceptance or flight readiness.

Real attempts also demonstrate unreliable complex declarations: a model may assign
both a mirror driver and an independent attachment/parameterization to one part.
Those conflicts fail explicitly after the bounded repair allowance. Keeping the
failures is necessary to distinguish an improved candidate from a reliable system.

## Validation

Initial implementation: 199 local tests and all ten GitHub CI jobs passed.
Corrected implementation: 203 local tests passed. A fresh installed wheel passed
CAD generation, independent Lean rechecking and MCP stdio integration. Those tests
validate software contracts; they do not establish visual fidelity.

The independent bundle verifier checks the archived manifests, model selection chain,
source/response commitments, nominal constraints and Lean manufacturing-plan closure.
Geometry metrics are measured separately by `scripts/measure_assembly.py` with the
predeclared pair list, without editing or selecting a candidate.

Both completed refinement runs remove all four legacy engine-axis diagnostics and
bring both predeclared wing/winglet surface gaps from approximately 15,351 mm to zero.
The initial six-round run reduces a declared pylon/nacelle contact gap from 31.3067 mm
to 0.276156 mm, then zero. Declared seams and contacts pass in the selected candidates.
These changes do not certify silhouette fidelity; visible floating or poorly placed
details remain, particularly in relationships declared only as placement.

Two of four attempts produced a reviewed, model-selected new design. The other two
failed safely and preserved the input, despite the manufacturing-plan proof passing.
Consequently this experiment does **not** establish that a larger review budget is
better: a run can fail before reviewing anything. Splitting complex declarations
into smaller validated stages is a remaining reliability improvement.

All four bundles passed their independent verifier. Both runtime commits passed all
ten GitHub CI jobs; the final runtime has 203 local passing tests. All four attempts
are retained in the local Studio history alongside the previous runs. Public website
recordings were not replaced by this engineering validation.

The Studio preserves all 21 recorded runs. Eight browser checks (four attempts at
1440px and 390px) verified correct selected/unreviewed cards, diagnostic visibility
and extended budget controls, with no page errors. Copied bundles retained all
manifest hashes. Desktop/mobile screenshots are archived with the evidence.
