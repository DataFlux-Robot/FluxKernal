# v0.8 — Cross-product recipe assets

Previously, Studio could cache unchanged CAD from a design's immediate parent.
It now publishes verified component, module and complete equipment-cell recipes into
an immutable content-addressed library, and instantiates them in other product runs.
Matching uses functional category, unit-aware operating ranges and declared interfaces.

The release adds bounded parameter bindings, derived geometric measures, capability
invalidation after adaptation, local-frame nominal constraints, explicit reintegration
obligations and pinned source/target identities. Imported CAD and manufacturing
evidence are regenerated. Existing unchanged target CAD retains its verified cache.
The CLI, five new MCP tools and a packaged agent skill expose the workflow.

## Local evidence

The [benchmark report](2026-09-28-v0.8-evidence/benchmark.json) records **9/9** expected
outcomes in 40.18 seconds, with **zero model calls**:

- Three controller instances: car → truck, aircraft and humanoid.
- Shaft adaptation to 16 mm in a humanoid subsystem.
- A bracket/shaft module rotated 90° in an aircraft subsystem.
- A complete equipment-cell recipe reused for the humanoid mounting blank.
- Rejection of an undersized cell, a voltage mismatch, and stale torque evidence.

All six accepted instances generated a new plan proof and passed an independent
bundle verifier. The report records preserved target requirements, unchanged parents
and rejected attempts producing no CAD. The accompanying `*-verify.txt` files retain
the actual Lean outputs. The real CAD fixtures contain three authored subsystem parts
each, plus manufacturing equipment; they are not whole vehicles or robots.

[Full regression](2026-09-28-v0.8-evidence/tests.txt): **227 passed**. A subsequent
[targeted check](2026-09-28-v0.8-evidence/targeted-tests.txt) covers the final asset/CLI
changes. Tests include real MCP publication/search/preflight/instantiation, framed
constraints surviving later revisions, strict numeric inputs, source hashes,
namespace collisions, procurement immutability and stale capability rejection.

## Scope

This release enables cross-product **recipe reuse**, not inherited physical
qualification. Capabilities are publisher declarations. Interface matching currently
uses exact identifiers; dimensional checks are nominal Python checks. Lean proves the
conditional manufacturing plan, not material strength, fit tolerances, aviation
certification or equipment performance. No supplier database is included.

GLM model/provider configuration is unchanged. The new asset tools are available to
the calling agent, but automatic asset selection inside `fk perceive` is not yet
implemented. No new live image-design trial or public website publication is claimed.
See [the API and workflow](../CROSS_PRODUCT_ASSETS.md) for reproduction and limits.
