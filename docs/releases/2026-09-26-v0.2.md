# FluxKernel v0.2 — portable onboarding and reproducible distributions

This iteration makes the existing prototype easier to install, inspect and extend.
It does not claim improved image reconstruction, qualified catalog data or verified
physical manufacturing capability. The repository remains private.

## User-visible changes

- English and Chinese README entry points, an actual Studio screenshot and linked
  quickstart, architecture, contribution, security and milestone documents.
- `fk doctor --profile core|studio|proof|live [--json]`, without model requests or
  automatic toolchain installation; diagnostics never print private configuration.
- `fk example`: a dependency-free, non-overwriting first design with distinct
  content identities for two parameter sets.
- `fk demo --reference phone|car|aircraft --output DIR --json` and
  `fluxkernel.studio.generate_reference()`. Each call creates a fresh run, captures
  native CAD logs and explicitly records reference mode.
- `--require-proof` rejects completed but unproven plans for automation.

## Defects fixed

- Wheels lacked the canonical Lean project and independent bundle verifier.
- Proof execution depended on the original repository directory.
- Installed Studio could attempt to store runs below its installation directory.
- The dependency-free kernel unconditionally imported the NumPy-backed sketch solver.
- Repeated Engine instances lost diagnostics for optional plugins that failed to load.
- Distribution smoke checks confused macOS symlink paths and Windows short paths with
  installation outside the isolated environment.

Proof inputs now have one canonical source, packaged at build time. Each run gets
its own writable Lean project; compiler cache files are excluded from the evidence
manifest. Existing source-checkout history remains at `.demo/runs/`.

## Validation

- Local full suite: 84 tests passed, followed by the added missing-Lean regression
  test passing separately (85 tests total).
- Wheel built from the source archive, installed in a fresh environment outside the
  checkout: dependency-free workflow passed without NumPy or OCP.
- Separate fresh-wheel demo environment: generated phone CAD, checked actual Lean,
  ran the independent verifier, and rejected a deliberately altered input image.
- A depth-zero equipment case remained open instead of silently removing machining
  requirements.
- Documentation links, `git diff --check`, and configured-credential scans passed.
- Local service restarted after checking for active jobs; health and history returned
  successfully, with the existing configured model and Lean launcher retained.

Remote CI: all 7 jobs passed on commit `7c48ffa5d47b464eef7f7c4db4572a30f1fc8db0`; the complete integration suite reports **85 passed**. Results are recorded in `2026-09-26-v0.2-ci.json`. The matrix covers
Python 3.12 and 3.13 across Linux, macOS and Windows for the core, plus Linux CAD,
actual Lean and installed-wheel integration. Native CAD on macOS/Windows has not
been claimed as validated by that core matrix.

## Delivery and follow-up

No PyPI upload or change to public visibility was performed. Build outputs are
`dist/fluxkernel-0.2.0-py3-none-any.whl` and `dist/fluxkernel-0.2.0.tar.gz`.
The existing public showcase still represents its earlier recorded runs.

The next engineering gate is a stable constraint-preserving revision API with small,
reproducible assembly tasks, followed by sourced catalog interfaces and measured
physical fit. See ROADMAP.md for acceptance criteria rather than star-count promises.
