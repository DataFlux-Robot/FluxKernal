# v0.6 — GLM-authored symmetry and parametric PAL

The task was to implement workflow/skill/tools while leaving all runtime design
choices to GLM-5.3-Flash. The implementation now uses GLM for symmetry assessment,
source/target pairing, exceptions, parameterization, reviews, edits and candidate
selection. Deterministic code supplies CAD construction, real reflections, rule
validation, recipe fact checks and evidence storage. No hand-written candidate or
parameter repair was injected into the live runs.

## Implemented

- A packaged runtime skill plus parameter reference, loaded into every model phase.
  Also linked into the local Codex skill directory for discovery and CLI invocation.
- Explicit symmetry modes, evidence/confidence, mirror plane, disjoint occurrence
  pairs and exceptions. Unknown/uncertain cases remain unmirrored.
- True local reflection plus rotation conjugation, verified for all three axes,
  preserving procurement dimensions and occurrence identities.
- Semantic wing controls and ordered elliptical body sections, with derived size,
  actual B-rep construction, STEP/STL export and bounded actions.
- Current parameter/difference tables and checked structured reviewer claims.
- GLM candidate selection and stopping; no host visual-ranking override.
- Common-frame comparison and an explicit separation of framing from structural errors.
- Workflow/skill hashes, model-response hashes and provider-reported identity in the
  evidence bundle. Independent verification checks the selection chain and final design.

## Frozen real-model validation protocol

Both products start from the same recorded original GLM designs used previously:
`2083c1262b24487a` (aircraft) and `b9f5ec651fd040fe` (car). The budget is three review
rounds; GLM can stop early. The baseline, prompts, candidates and selections are not
manually patched during a run.

First frozen implementation: `f1999a321efcc0d8855a8c9a74aedbe82e764fb5`.
Both first runs stopped before review: aircraft returned descriptive sentences in
an exact-ID exceptions field even after one correction; car returned invalid JSON.
The original designs and all failures were preserved. These are protocol failures,
not successful symmetry/parametric design results.

After both runs ended, the generic workflow contract was corrected: actual part-ID
enums and precise validation feedback, plus bounded model repair for JSON parsing
errors. No product-specific IDs or desired numeric geometry were added to the skill.
The corrected implementation was frozen as `4411aa548fc2daca67468ef99ab249e6cf35ab53`,
and two new runs were started from the same original parents. The first attempts
remain in the complete ledger; no prettier candidate is substituted by the operator.

## Boundaries

This is an OpenVSP-inspired finite parameter system, not an OpenVSP integration.
The new bodies/wings are concept solids, not verified thin-walled aircraft structures.
No aerodynamic, manufacturing or camera-pose validation is claimed. Symmetry applies
only to GLM-declared pairs. Structured fact checking does not prove all free-text
criticism. Additional iterations are not promised to yield high fidelity.

See [workflow behavior](../PERCEPTION_ACTION_LOOP.md) and the
[runtime skill](../../fluxkernel/demo/skills/fluxkernel-glm-pal/SKILL.md).
